# iOS app configuration (`forge.toml`)

An iOS app's settings are spread over several files: `Info.plist` (name, version, permission prompts, URL schemes), the entitlements file (app groups, push, universal links), `xtool.yml` (bundle ID, which product to build), `Package.swift` (deployment target) and, on a Mac, the Xcode project. In a Forge app you set all of them in one place, `forge.toml`, and Forge writes the files.

```
forge.toml ──forge build/run ios, forge config sync──▶ Info.plist
                                                        App.entitlements
                                                        xtool.yml
                                                        Package.swift  (.iOS(...) only)
```

- `forge build ios`, `forge run ios` and `forge init` write the files every time, so editing `forge.toml` is enough. `forge config sync` does it on its own.
- `forge config check` changes nothing and fails if a file is out of date. Run it in CI.
- `forge config show` prints the effective settings, plus anything worth knowing (paid-team entitlements, icon size, Xcode settings that differ).

The generated files start with a `Generated by Forge from forge.toml` comment. Commit them with the app: xtool and Xcode read them directly, and a reviewer sees what changed. Don't edit them by hand, because the next build overwrites them.

Everything below works on Linux with xtool. The Xcode project is the optional macOS path ([ios-xcode.md](ios-xcode.md)).

## A complete example

```toml
[app]
name = "PocketLibrary"
bundle_id = "org.example.pocketlibrary"
minimum_ios = "17.0"
display_name = "Pocket Library"     # home-screen name (default: name)
version = "1.2.0"                   # CFBundleShortVersionString (default 1.0.0)
build_number = "7"                  # CFBundleVersion (default 1)

[rust]
path = "rust"

[build]
ios_device = true

[ios]
icon = "Resources/AppIcon.png"      # 1024x1024 PNG, no transparency
orientations = ["portrait"]         # portrait, portrait_upside_down, landscape_left, landscape_right
url_schemes = ["pocketlibrary"]     # opens pocketlibrary://... links
background_modes = ["fetch"]

[ios.permissions]
camera = "Scan a book's barcode to add it."
photo_library = "Choose a cover photo for a book."

[ios.entitlements]
app_groups = ["group.org.example.pocketlibrary"]
data_protection = "complete"

[ios.signing]
team_type = "free"                  # "free" (Apple ID) or "paid" (Developer Program)

[ios.info]                          # any other Info.plist key, written as-is
ITSAppUsesNonExemptEncryption = false
```

Forge checks every value when it reads `forge.toml`, so a typo fails the next command with the fix rather than failing on the phone. For example: `[ios.permissions] unknown permission "camra". Use one of: bluetooth, calendars, camera, ...`.

Forge also warns, without stopping the build, when the app's Rust crate selects an [optional native service](native-services.md#optional-services) that needs a permission (`location`, `motion`, `bluetooth`) and `[ios.permissions]` has no text for it. It reads the selection from `Generated/ForgeFFI/ForgeServices+Selected.swift`, so the check starts working once bindings have been generated. The warning ends with the exact line to add, for example `location_when_in_use = "<why the app needs it>"`, for you to fill in with your own sentence.

## Reference

### `[app]`

| Key | Info.plist / build | Default |
|---|---|---|
| `name` | Project name; the home-screen name unless `display_name` is set | required |
| `bundle_id` | `xtool.yml` `bundleID` | required |
| `minimum_ios` | `Package.swift` `.iOS("…")`, which xtool turns into `MinimumOSVersion` | required for iOS |
| `display_name` | `CFBundleDisplayName` | `name` |
| `version` | `CFBundleShortVersionString` (1 to 3 numbers) | `1.0.0` |
| `build_number` | `CFBundleVersion` | `1` |

When `minimum_ios` changes, Forge rewrites the `.iOS(...)` entry in `Package.swift`'s `platforms`. That is the only line of `Package.swift` it touches.

### `[ios]`

| Key | Writes | Notes |
|---|---|---|
| `xtool_product` | `xtool.yml` `product` | The SwiftPM library product holding `@main`. `forge init MyApp` sets `MyAppXtool`. It is the app's executable, so it is the process name in the phone's log and on crash reports. Default when unset: `AppHostXtool` (apps made before 2026-11-07). Change it together with the `.library(name:)` in `Package.swift`. |
| `icon` | `xtool.yml` `iconPath` | A PNG inside the app. Use 1024x1024 with no alpha channel. xtool copies it into the app and sets `CFBundleIconFile`; iOS scales it. |
| `orientations` | `UISupportedInterfaceOrientations` | Default `["portrait"]`. |
| `url_schemes` | `CFBundleURLTypes` | Custom schemes for deep links. System schemes (`https`, `tel`, …) are refused: use `associated_domains` for https links. |
| `background_modes` | `UIBackgroundModes` | `audio`, `bluetooth-central`, `bluetooth-peripheral`, `external-accessory`, `fetch`, `location`, `nearby-interaction`, `processing`, `push-to-talk`, `remote-notification`, `voip`. |
| `background_tasks` | `BGTaskSchedulerPermittedIdentifiers` | Background task identifiers for the `background` native service ([native-services.md](native-services.md#background-tasks-background)), such as `["org.example.app.refresh"]`. Also adds the `fetch` and `processing` background modes. Works on a free team. |
| `info` | any Info.plist key | Strings, booleans, numbers, arrays and tables. Keys that Forge sets elsewhere are refused (set them in one place), as are `CFBundleIdentifier`, `CFBundleExecutable` and `MinimumOSVersion`. |

### `[ios.permissions]`: permission prompts

iOS refuses (and App Review rejects) a permission request without a usage description. Each entry is the sentence iOS shows in the prompt.

| Name | Info.plist key |
|---|---|
| `bluetooth` | `NSBluetoothAlwaysUsageDescription` |
| `calendars` | `NSCalendarsFullAccessUsageDescription` |
| `calendars_write_only` | `NSCalendarsWriteOnlyAccessUsageDescription` |
| `camera` | `NSCameraUsageDescription` |
| `contacts` | `NSContactsUsageDescription` |
| `face_id` | `NSFaceIDUsageDescription` |
| `health_share` / `health_update` | `NSHealthShareUsageDescription` / `NSHealthUpdateUsageDescription` |
| `homekit` | `NSHomeKitUsageDescription` |
| `local_network` | `NSLocalNetworkUsageDescription` |
| `location_when_in_use` | `NSLocationWhenInUseUsageDescription` |
| `location_always` | `NSLocationAlwaysAndWhenInUseUsageDescription` (also needs `location_when_in_use`) |
| `media_library` | `NSAppleMusicUsageDescription` |
| `microphone` | `NSMicrophoneUsageDescription`; needed by the optional `audio` native service ([native-services.md](native-services.md#audio-audio)) |
| `motion` | `NSMotionUsageDescription` |
| `nfc` | `NFCReaderUsageDescription` |
| `photo_library` / `photo_library_add` | `NSPhotoLibraryUsageDescription` / `NSPhotoLibraryAddUsageDescription` |
| `reminders` | `NSRemindersFullAccessUsageDescription` |
| `speech_recognition` | `NSSpeechRecognitionUsageDescription` |
| `tracking` | `NSUserTrackingUsageDescription` |

A raw key ending in `UsageDescription` also works, for anything not in the table. Local notifications need no entry: the app asks at runtime.

### `[ios.entitlements]`

| Key | Entitlement | Team |
|---|---|---|
| `app_groups = ["group.…"]` | `com.apple.security.application-groups` | free or paid |
| `data_protection = "complete" \| "unless_open" \| "until_first_auth"` | `com.apple.developer.default-data-protection` | free or paid |
| `healthkit = true` | `com.apple.developer.healthkit` | free or paid |
| `homekit = true` | `com.apple.developer.homekit` | free or paid |
| `associated_domains = ["applinks:example.com"]` | `com.apple.developer.associated-domains` (universal links, password autofill) | **paid** |
| `push_notifications = "development" \| "production"` | `aps-environment` | **paid** |
| `sign_in_with_apple = true` | `com.apple.developer.applesignin` | **paid** |
| `[ios.entitlements.extra]` | any other key, written as-is | depends |

Forge always writes `App.entitlements`, even when it is empty, so the Xcode project's `CODE_SIGN_ENTITLEMENTS` always finds it. `xtool.yml` only points at it when it has entries.

The Keychain needs no entitlement for the app's own items. Add `keychain-access-groups` under `extra` only to share items between apps.

### `[ios.signing]`

Forge never stores Apple credentials. xtool signs with the account you signed in with (`xtool auth`, see [ios-signing.md](ios-signing.md)).

| Key | Use |
|---|---|
| `team_type = "free" \| "paid"` | Which kind of team xtool signs with. With `"free"`, Forge refuses entitlements Apple only provisions for the Apple Developer Program, and says which one, before anything is built. Left unset, Forge prints a warning for them instead. |
| `team_id = "ABCDE12345"` | Your 10-character team ID. Used to check the Xcode project's `DEVELOPMENT_TEAM` (`forge config check` reports a mismatch). |

### `[ui_test]`

How UI automation runs the app. Nothing here is written into the app; the app itself must honour the argument.

| Key | Use |
|---|---|
| `test_data_args = ["-ForgeUITestData"]` | Launch arguments that start the app on fresh, throwaway data instead of the person's own. `forge ui explore` refuses to change data without them ([forge-explore.md](forge-explore.md#test-data)). Pocket Library honours `-ForgeUITestData` by using an emptied `PocketLibrary-UITest` folder |
| `real_data_safe = ["library.settings"]` | Identifiers `forge ui explore --real-data` may tap besides navigation (rows, tabs, back, cancel), because you know they change nothing. Never overrides the never-lists ([forge-explore.md](forge-explore.md#test-data)) |

## Debug and release builds

| Command | Swift configuration | Rust library |
|---|---|---|
| `forge build ios`, `forge run ios` | debug (`xtool dev build`) | release profile |
| `forge build ios --release`, `forge run ios --release` | release (`xtool dev build -c release`) | release profile |

The Rust library is optimised in both. Set `FORGE_IOS_PROFILE=debug` for an unoptimised one. Both configurations are development builds signed for your own devices; App Store distribution is not supported yet ([builds.md](builds.md)).

## Xcode (macOS, optional)

Apps from `forge init` have an Xcode project whose app target reads the generated files: `INFOPLIST_FILE = ../Info.plist` and `CODE_SIGN_ENTITLEMENTS = ../App.entitlements`. So display name, version, permissions, URL schemes, background modes and entitlements reach Xcode builds too. The bundle ID, deployment target and team remain Xcode build settings. Forge does not edit the Xcode project; `forge config check` and `forge config show` list any that differ from `forge.toml`, with the setting to change.

## Icons and launch screen

`icon` is a single 1024x1024 PNG. xtool cannot compile asset catalogs (`Assets.xcassets`) on Linux, so alternate icons, dark and tinted variants, and launch images from an asset catalog are not available in xtool builds. The launch screen is iOS's default (a blank screen in the system background colour, `UILaunchScreen`), which is what Apple recommends for apps that draw their first screen quickly. You can still set `UILaunchScreen` through `[ios.info]`, but values that name asset-catalog colours or images have not been tested with xtool.

## Adding dependencies

### Rust crates

The app's Rust code is its own crate in `rust/` ([app-crate.md](app-crate.md)). Add crates as usual:

```bash
cargo add --manifest-path rust/Cargo.toml chrono
cargo test --manifest-path rust/Cargo.toml
forge run ios      # rebuilds the static library because rust/ changed
```

Every crate must build for `aarch64-apple-ios` (and the Android targets, if you build for Android):

- Pure-Rust crates just work. Check with `cargo check --manifest-path rust/Cargo.toml --target aarch64-apple-ios`.
- Crates with C code build with the Darwin SDK that `xtool setup` installed; `forge build ios` finds it for you.
- Avoid crates that link system libraries the iPhone does not have, such as OpenSSL: use rustls (as `forge-net` does).
- Code that touches iOS frameworks (for example `Security` or `CoreFoundation`) needs the framework linked in `Package.swift` (`.linkedFramework("…")` on the `ForgeFFI` target), because a static library does not carry its framework dependencies.
- Keep `uniffi` at the version `forge init` pinned: the bindings generator must match it.

### Swift packages

xtool builds the app with SwiftPM, so Swift packages work on Linux as they do on a Mac. In `Package.swift`, add the package and use its product in `AppHost` (the target with your SwiftUI code):

```swift
dependencies: [
    .package(url: "https://github.com/apple/swift-collections", from: "1.1.0"),
],
targets: [
    .target(
        name: "AppHost",
        dependencies: [
            "ForgeFFI",
            .product(name: "Collections", package: "swift-collections"),
        ],
        path: "Sources/AppHost"
    ),
    // ...
]
```

- The package must support iOS at your `minimum_ios` or lower.
- Commit `Package.resolved` so every machine builds the same versions.
- Packages with resources work: xtool copies their bundles into the app.
- Binary packages (`.binaryTarget`, an `.xcframework`) work if they include an `ios-arm64` slice; xtool embeds and signs dynamic frameworks, and static ones are linked in.
- Packages that need an Xcode build plugin, asset catalogs or storyboards will not build with xtool on Linux.
- Leave the `.iOS(...)` platform alone: Forge keeps it equal to `minimum_ios`.
- The Xcode project uses the same `Package.swift` (it references the package locally), so Xcode picks the dependency up too.

## Apps made before Forge generated these files

Apps from an earlier `forge init`, and apps with a hand-edited `Info.plist` or `xtool.yml`, keep working. On the first `forge build ios` (or `forge config sync`), Forge replaces a hand-written file only if nothing in it would be lost, that is when `forge.toml` already produces every value in it. Otherwise it stops and names the file. Move its keys into `forge.toml` (permission texts into `[ios.permissions]`, other keys into `[ios.info]`, a different `product` into `[ios] xtool_product`) and build again, or run `forge config sync --force` to replace it anyway.

An older Xcode project does not read the generated files; `forge config check` says so and names the two settings to add.
